# 业务分支与场景检查清单

每分析一个核心操作，都从以下维度检查是否存在不同情况。

## 状态差异
- 当前状态不同，操作是否不同？
- 已提交后还能否修改？
- 已审核后还能否撤回？
- 已结束后还能否重开？
- 是否有中间、失败、历史状态？

## 角色差异
- 不同角色看到/能做的是否不同？
- 是否有本人、本学院、全校等数据范围？
- 是否存在管理员强制处理？

## 类型差异
- 不同业务类型是否走不同流程？
- 某些类型是否跳过某个环节？

## 配置差异
- 是否有启用/停用？
- 是否可选择是否审核、是否评审、是否中期检查？
- 配置作用在全局、类型、批次还是个人？

## 时间差异
- 是否必须在开放期内操作？
- 超期后如何处理？
- 是否自动关闭或允许延期？

## 数量与阈值
- 是否有人数、专家数、次数、得分线、比例、名额限制？

## 异常路径
主动寻找：驳回、退回、撤回、重提、作废、取消、终止、暂停、恢复、延期、强制结束、人工干预、重复提交、数据缺失、超时。

## 场景成立条件
一个场景至少写清：

**谁 → 对什么对象 → 当前什么状态 → 满足什么条件 → 做什么 → 结果如何**。

不要机械做角色×状态×类型×配置的笛卡尔积，只保留系统真实可达的组合。
