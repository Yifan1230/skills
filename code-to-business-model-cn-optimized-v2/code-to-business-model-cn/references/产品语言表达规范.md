# 产品语言表达规范

## 总原则
主文档回答“业务怎么运行”，技术信息只回答“这个结论从哪里来的”。

## 示例

不写：`status=2 时显示 auditBtn`。

写：当申请处于“待审核”状态时，审核人员可以执行审核。

不写：SQL 根据 `dept_id` 过滤。

写：学院管理员默认只能查看本学院范围的数据。

不写：`needReview=true` 时进入 ReviewService。

写：当项目配置为“需要专家评审”时，审核通过后进入专家评审环节。

## 技术证据
正文写业务结论；证据表只保留最小定位，例如：

> 证据来源：项目申请审核处理逻辑 / 驳回分支。

除非用户明确要求，不在主文档展开类名、方法参数、SQL和代码片段。
