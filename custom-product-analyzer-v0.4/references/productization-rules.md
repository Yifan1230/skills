# Productization Rules

## 目标

本阶段不是给 Feature 打一个技术标签，而是帮助产品经理判断：

> 真正的业务问题是什么？标品为什么导致客户反复定制？应该建设哪一种通用产品能力？

在进入本文件前，必须先按照 `product-problem-analysis.md` 完成“业务场景 → 产品问题 → 根因 → 优化目标 → 产品能力方案”的翻译。

---

## 一、先判断是不是产品问题

只有满足以下条件的变化才进入产品化分析：

- 用户/管理员能够感知到业务行为差异；或
- 改变了业务规则、流程、权限、字段、操作方式、数据口径；或
- 多客户通过定制反复绕过同一个标品限制。

纯技术实现变化默认不进入产品方向。

---

## 二、产品化判断维度

### repeat_frequency
多少独立客户出现类似业务问题。

### cross_customer_generality
问题是否跨客户仍然成立，而不是某校独有制度。

### variant_diversity
同一能力出现多少种业务变体。

高 variant diversity 往往说明标品不应继续硬编码一种规则，而应建设可配置能力。

### maintenance_duplication
是否存在多客户重复开发、重复测试、重复维护同类定制。

### standard_product_gap
当前标品的产品能力缺口属于什么：

- 固定值写死
- 条件维度不足
- 流程强绑定
- 字段不可扩展
- 权限粒度不足
- 规则不可组合
- 适用范围不可配置
- 页面操作缺乏通用入口

### customer_specificity
是否高度依赖某校政策、组织、接口或历史系统。

### baseline_reliability
若基线弱，则产品判断也必须降级。

## 三、内部推荐枚举

内部 JSON 可使用：

- strong_productization_candidate
- productization_candidate
- configuration_candidate
- observe
- keep_custom

但产品经理报告必须翻译：

| 内部枚举 | 用户可见表达 |
|---|---|
| strong_productization_candidate | 高优先级标品优化 |
| productization_candidate | 建议纳入标品能力 |
| configuration_candidate | 建议做成可配置能力 |
| observe | 证据不足，继续观察 |
| keep_custom | 建议保持定制/技术特例 |

注意：这只是“建议类型”，不是主结论。

## 四、常见抽象模式

### 高频值变化

不要：

```text
增加 3 人、5 人等更多固定选项。
```

应考虑：

```text
允许业务管理员配置人数参数，并定义适用范围。
```

### 高频维度变化

例如规则反复增加学院、年级、培养层次。

不要：

```text
把这三个字段都加进标品。
```

优先判断：

```text
是否需要“规则条件配置”，让管理员选择可用维度并组合条件。
```

### 高频流程节点变化

优先判断：

```text
流程是否需要可编排、节点是否需要可选、顺序是否需要可配置。
```

### 高频字段变化

优先判断：

```text
是否需要表单字段扩展/动态字段能力。
```

### 高频权限变化

优先判断：

```text
授权对象、数据范围、操作权限粒度是否不足。
```

### 高频校验变化

优先判断：

```text
校验条件、校验级别、提示信息、生效范围是否需要配置化。
```

## 五、产品方案必须达到的具体度

不合格：

```text
建议配置化。
```

合格：

```text
建议在“学生名单导入”中增加校验规则配置能力，由管理员配置准入条件、阻断/提醒级别、适用范围和错误提示。已发现的客户变体涉及年级、培养层次、学籍状态；这些维度可作为第一批候选，但上线范围仍需结合更多客户证据确认。
```

产品方案不得凭空发明证据中没有出现的业务能力。

---

## 六、反证要求

每个推荐必须回答：

- 为什么这是产品问题而不是技术差异？
- 为什么不应继续客户定制？
- 为什么不应该只增加一个固定功能？
- 是否有客户特有政策可以解释这些差异？
- 是否可能只是版本差异？
- 产品能力泛化后是否会显著增加复杂度？
- 当前证据真正支持到什么粒度？

---

## 七、最终产品方向表的最低要求

每一行必须至少包含：

- 产品问题
- 业务场景/影响
- 客户定制共性
- 根因判断
- 优化方向
- 建议类型
- 证据客户
- 置信度

不能只输出：

```text
Feature + recommendation enum + confidence
```
