# 配置边界判断

## 1. 配置应该归属哪里

优先从业务稳定性判断：

```text
系统全局
→ 业务类型/种类
→ 业务批次
→ 组织
→ 具体对象
→ 个人
```

越靠上，配置影响范围越大，应越稳定。

越靠下，越适合执行期或个体差异。

---

## 2. 判断问题

每个配置至少回答：

- 这个规则多久变化一次？
- 谁有权修改？
- 修改后影响已有数据还是只影响新业务？
- 是否需要继承上级默认值？
- 下级是否允许覆盖？
- 是否需要版本化？
- 是否存在生效时间？

---

## 3. 常见错误

### 错误1：把所有配置放在批次

结果：每开一次批次都重复配置稳定规则。

### 错误2：把执行信息放在类型层

结果：每期变化的数据污染长期规则。

### 错误3：没有默认值

结果：所谓灵活配置变成实施负担。

### 错误4：配置互相组合失控

结果：理论支持很多情况，但没人知道哪些组合合法。
