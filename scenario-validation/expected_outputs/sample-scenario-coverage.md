# 场景兼容与验收（示例）

## 1. AS-IS / TO-BE场景兼容

| AS-IS场景 | TO-BE场景 | 处理方式 | 差异 | 结论 |
|---|---|---|---|---|
| 正常提交申请 | 正常提交申请 | 保留 | 增加提交前自动校验 | 接受 |
| 审核驳回后修改 | 驳回后重提 | 优化后保留 | 状态更清晰 | 接受 |
| 审核中撤回 | 审核中撤回 | 保留 | 由批次规则控制 | 接受 |
| 某校特殊领导会签 | - | 有意废弃/待确认 | 无标准替代 | 待决策 |

## 2. 关键规则覆盖

| 规则 | 正向 | 反向 | 异常 | 边界 | 状态 |
|---|---|---|---|---|---|
| 只有开放期可提交 | ✓ | ✓ | - | 截止时刻 | 通过 |
| 只有本学院审核人可审核 | ✓ | ✓ | - | 多身份用户 | 通过 |
| 评审中不可撤回 | ✓ | ✓ | ✓ | - | 通过 |

## 3. 验收用例

### AC-023 审核中允许撤回

角色：申请人  
状态：学院审核中  
配置：允许撤回=是

操作：撤回申请。

预期：

- 申请回到草稿状态；
- 原审核待办失效；
- 申请恢复可编辑；
- 已记录撤回操作。

反向：允许撤回=否时，不应允许执行撤回。
