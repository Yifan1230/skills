# 多 Agent 冲突与 Decision Log

## 一、冲突类型

多 Agent 结论不一致时，先判断属于哪类冲突。

### 1. 事实冲突

例如：

- 一个 Agent 认为状态5表示“专家评审”；
- 另一个 Agent 认为状态5表示“审核完成”。

处理方式：补证据，不投票。

### 2. 定义冲突

例如：

- 一个 Agent 把“项目申请”视为独立业务对象；
- 另一个 Agent 把它视为“项目”的一个阶段。

处理方式：回到对象定义、生命周期和数据事实统一口径。

### 3. 设计冲突

例如：

- 方案A把评审规则放在项目种类；
- 方案B放在项目批次。

处理方式：进入 Decision Log，比较方案，不伪装成事实问题。

---

## 二、冲突处理流程

```text
发现冲突
→ 建立冲突项
→ 收集各自证据
→ 判断冲突类型
→ 指派最小范围补充分析
→ 得出结论
→ 更新主档
→ 必要时建立 Decision Log
```

不要让多个 Agent 各自保留一个“最终结论”。

---

## 三、Decision Log 模板

```markdown
# DEC-001 [决策名称]

## 问题
[需要决定什么]

## 现状证据
- FACT：...
- FACT：...
- INFERENCE：...

## 备选方案

### 方案A
优点：
风险：

### 方案B
优点：
风险：

## 判断维度
- 行业共性
- 用户理解成本
- 配置复杂度
- 迁移影响
- 扩展性
- 实施成本

## 最终决定
[决定]

## 原因
[为什么]

## 影响范围
- 业务对象
- 流程
- 页面
- 配置
- 数据迁移

## 状态
已确认 / 待确认 / 已废弃
```

---

## 四、Decision Log 适用范围

以下决定建议记录：

- 核心业务对象拆分/合并；
- 生命周期重大变化；
- 规则放在哪个层级；
- 是否配置化；
- 是否废弃旧能力；
- 历史兼容策略；
- 高影响体验设计选择。

普通按钮位置和轻量视觉细节不需要进入 Decision Log。
